    How CRC-16 / MODBUS is calculated
    Start at 0xFFFF. XOR each byte into the low byte of the CRC. Repeat 8 times: save bit 0, shift right one bit, then XOR 0xA001 if the saved bit was 1. No final XOR. Append the low CRC byte first.
    crc = 0xFFFF
for each byte in payload:
    crc = crc XOR byte
    repeat 8 times:
        lowBit = crc AND 1
        crc = crc >> 1
        if lowBit == 1: crc = crc XOR 0xA001
send payload + [crc AND 0xFF, crc >> 8]
    For 01 03 00 00 00 01, CRC = 0x0A84; the wire carries 84 0A. CRC covers the Unit ID, function and data, but excludes the CRC field itself. Rechecking a complete valid RTU frame gives residue 0x0000.
    Parity checks each UART character. The 8-bit sum here is a teaching comparison, not Modbus ASCII LRC. RTU uses CRC-16; Modbus TCP does not carry an RTU CRC. These checks detect errors, not deliberate tampering. This comparison is independent of the UART settings above.

    Timing, parity and simulator scope
    Tbit = 1/baud. Tchar = (1 start + 8 data + parity bits + stop bits)/baud. E/O uses one parity bit; N uses none. For 9600 8E1, Tchar = 11/9600 = 1.146 ms. Data bits travel LSB first; bytes within a Modbus register travel high byte first. The RTU CRC low byte travels first.
    The ideal receiver detects a falling start edge and samples bit centres. It models configuration mismatch and a single-bit error, but not oversampling, jitter, electrical noise, line termination or a full hardware UART. Some mismatched configurations can still decode a particular pattern. Modbus trials assume valid inter-frame spacing and an immediate server response; timeout means no valid response in this teaching transaction, not measured elapsed wall time.
    TCP mode constructs MBAP/PDU messages for comparison. The separate fixed walkthrough illustrates handshake and buffering, not a full TCP stack. No PCAP is generated. CRC checks transmission integrity, not measurement accuracy or authorization.
